# Roblox 적용 절차와 QA

확인일: 2026-10-29. 이 문서는 적용 지침이며 업로드·심사·실행 완료 증빙이 아니다.

## 파일 선택

- `audio/bgm/`: M01–M24, F01–F10의 루프 초안 34개.
- `audio/jingles/`: J01–J16의 짧은 이벤트 음악 16개. 반복 재생하지 않는다.
- `audio/promo/`: F11/F12의 15·30·60초 영상용 편집본 6개. 게임 업로드 목록에서 제외했다.
- 처음 적용할 때는 M01–M16을 우선 사용한다. 징글도 실제 구현된 이벤트만 연결한다.
- 원본 후보와 WAV 편집본은 [음악 릴리스](https://github.com/zaelee/ZZEE/releases/tag/pupsters-music-20261029)에 별도 보관한다. 원곡 선택을 바꾸면 편집·파일 검사를 다시 한다.

## 파일 규격과 업로드

Roblox 공식 안내는 MP3·OGG·WAV·FLAC의 단일 오디오 스트림, 20MB 미만, 7분 미만, 48kHz 이하를 요구한다. 이 폴더는 44.1kHz 스테레오 OGG 파일을 제공하며 실제 파일별 결과는 `data/audio-files.json`에 있다. 규격 통과는 플랫폼 심사나 권리 확인의 통과를 의미하지 않는다. [Roblox Audio assets](https://create.roblox.com/docs/audio/assets)

1. 사용할 음악을 청취하고 게임 배포에 필요한 사용 권리를 확인한다. 생성 당시 계정의 권리·플랜 증빙은 계정 소유자가 별도 보관한다. 이 인수인계는 별도 음원 재사용 라이선스를 선언하지 않는다.
2. 실제 경험을 소유한 사용자/그룹을 확인하고 Roblox Studio의 Asset Manager 또는 Creator Dashboard에서 선택한 파일을 업로드한다.
3. 심사와 업로드 결과를 확인해 자산 ID를 받는다. `data/roblox-upload-register.csv`에 실제 ID, 소유자, 허용 경험, 심사 상태를 기록한다. 빈 ID는 미업로드/미연결 상태로 남겨 둔다.
4. 비공개 오디오의 경험 사용 권한을 설정하고 실제 게시된 경험에서 재생되는지 확인한다. Studio에서 계정 소유자에게 들린다고 다른 플레이어에게도 들린다고 추정하지 않는다.
5. `AudioPlayer` 또는 기존 프로젝트의 오디오 계층에 자산 ID를 연결한다. GitHub의 URL이나 로컬 파일 경로를 Roblox 자산 ID로 대신하지 않는다.

월별 업로드 한도는 계정 인증 상태와 실제 업로드 화면에서 확인한다. 공식 오디오 안내와 Open Cloud 개별 문서의 한도 표기가 달라, 이 인수인계는 특정 계정의 잔여 한도를 가정하지 않는다. [오디오 안내](https://create.roblox.com/docs/audio/assets), [Open Cloud 자산 안내](https://create.roblox.com/docs/cloud/guides/usage-assets)

짧은 스킨·가방·프로필·설정 모달은 원래 BGM을 유지한다. 장시간 머무는 독립 화면이라면 M17–M20을 선택적으로 사용한다. M21·M24와 F계열은 해당 연출이 구현된 경우에만 연결한다.

크로스페이드 1.5–2.5초, 편집본 약 −18 LUFS-I/−1dBTP 이하를 작업 출발점으로 사용한다. 이는 Roblox 의무 음량 규격이 아니다. 실제 게임 효과음과 기기에서 최종 조정해야 한다.

## 구현 시 확인할 동작

- 같은 cue 요청은 유지하고, 새 cue 전환은 이전 비동기 로딩·페이드를 취소한다. 짧은 시간에 여러 화면을 오가도 마지막 상태의 음악만 남아야 한다.
- 전환 중 두 BGM의 짧은 겹침만 허용한다. 페이드 완료 후 이전 인스턴스와 이벤트 연결을 정리한다.
- 징글은 BGM과 분리하고 중요한 이벤트 동안만 BGM을 잠시 낮춘 뒤 원래 설정값으로 복귀한다. 사용자 음소거/음량 변경을 복귀 처리로 덮어쓰지 않는다.
- 라운드·보상·진화 등 이벤트 ID를 기준으로 중복 재생을 막는다. 징글 때문에 화면 전환·다음 웨이브를 지연시키지 않는다.
- 빈/거부된/권한 없는 자산 ID는 조용히 실패하고 제한된 횟수로만 재시도한다. 실패 루프로 네트워크 요청이나 인스턴스가 쌓이지 않게 한다.
- 초기 실행에 모든 원본 144개를 가져오지 않는다. 현재 곡과 가까운 전환 후보만 미리 준비한다.
