# 사고멍치 UI·아트·레벨·재화 개편 요청서

작성일: **2026-10-28**. 전투·특전 상세는 [전투 MD](PUPSTERS_GAMEPLAY_REWORK_REQUEST.md)를 함께 적용한다. 이 파일은 **수정할 요구사항과 완료 기준**이며 실제 수정 완료 보고서가 아니다.

## 0. 적용 원칙과 우선순위

**사용자 확정 요구**와 **구현 권장안/미결정**을 구분한다. 사용자가 지적한 현상은 실제 최신 게임에서 재현하고, 현재 화면·수치·파일을 확보한 뒤 수정한다. 이 전달본 작성 단계에서는 최신 14종 게임과 아이폰 화면을 직접 검사하지 않았다.

1. P0: 전체 화면 가림막 오류, 안전 영역·잘림·스크롤, 전투 맵과 소환창, 공격 중 크기 변화.
2. P1: 빌리지·맵 선택·티어·프로필·스킨·특전 화면의 정보와 아트 연결.
3. P1: 전투 MD의 지원견·반응·합체 개편 및 레벨·해금·조각·티켓·멍코인 규칙 통합.
4. P2: 조합 트리별 스킨 콘셉트 보드, 연출 정리, 실제 전투·경제·기기별 최종 QA.

티어(C–S), 전투 중 성장/최종 진화, 계정 레벨, 스킨 등급, 특전 해금은 서로 다른 개념이다. 문구와 아이콘을 섞지 않는다. 사용자가 요청하지 않은 새 등급·과금·확률 뽑기는 추가하지 않는다.

## 1. 전체 화면 레이아웃과 안전 영역

### UI-01. 전투 맵은 모두 가로형

- **확정:** 게임 진입 후 모든 전투 맵을 가로형으로 구성한다. 강아지 생성창을 열었을 때 맵과 창이 딱 맞아야 한다.
- 맵 자체의 종횡비·카메라/표시 영역을 맞춘다. 세로 맵을 단순히 가로로 늘려 길·캐릭터가 찌그러지게 하지 않는다.
- 소환창 닫힘/열림, 타워 미선택/선택, 배치 미리보기 상태를 각각 설계한다. 창을 열어도 입구·출구·핵심 경로·배치 타일을 판단할 수 있어야 한다.
- UI 크기를 바꿨을 때 실제 클릭/터치 좌표와 배치 판정도 일치해야 한다.

### UI-02. 공통 창의 좌우 경계

- **확정:** 스킨·티어·커뮤니티·가방·특전 창은 상단 왼쪽 Roblox 기본 UI 박스와 오른쪽 설정 UI 박스의 끝선을 기준으로 공간을 최대한 활용해 다시 설계한다.
- 현재 화면을 캡처해 두 기준 박스의 실제 가로 경계를 기록한다. 공통 창의 외곽이 이 구간에 맞도록 공유 레이아웃을 만든다. 기본 UI를 가리거나 누를 수 없게 만들지 않는다.
- 기본 UI 크기·안전 영역이 다른 기기에서는 실측 가능한 안전 경계를 따른다. 한 해상도의 고정 좌표를 전 기기에 복제하지 않는다.
- 제목·닫기·주요 액션은 고정, 내용만 필요할 때 스크롤. 창마다 제각각인 여백·최대 높이·닫기 위치를 정리한다.

### UI-03. 아이폰 16에서 빌리지를 조금 오른쪽으로

- **확정:** 가로 아이폰 16 기준 왼쪽 데드 스페이스를 고려해 중앙의 빌리지 화면을 약간 오른쪽으로 옮긴다.
- 물리 화면의 정중앙과 실제 사용 가능한 영역의 중앙을 구분한다. 왼쪽 안전 영역을 반영한 후 필요한 작은 보정을 더한다.
- 오른쪽 버튼을 누르기 어렵게 밀거나 모든 기기에 같은 오프셋을 강제하지 않는다. 반대 방향 가로 회전도 확인한다.
- 배경·건물·분수·터치 영역·이름표를 같은 좌표 기준으로 움직인다. 배경만 이동하고 클릭 영역은 남기는 오류를 피한다.

## 2. 빌리지·설정창

### UI-04. 건물·분수와 이름표

- **확정:** 빌리지 배경 중앙의 건물과 분수가 의도한 위치에 있지 않으므로 위치를 맞춘다.
- 최신 배경 원화와 화면을 대조해 광장/길/건물 받침에 맞게 기준점을 재설정한다. 건물·분수·이름표·클릭 영역의 전후 화면을 남긴다.
- **확정:** 빌리지 건물 이름 옆 장식 강아지들을 제거한다. 건물 이름 자체와 이동/진입 기능은 유지한다.

### UI-05. 설정창 스크롤과 구획

- **확정:** 게임 중 설정의 과도한 스크롤을 줄여 최적화한다. 글자를 지나치게 줄여 억지로 한 화면에 넣지 않는다.
- 자주 쓰는 설정은 상단에 묶고, 높이·행간·구획을 조정한다. 내용이 넘칠 때만 단일 세로 스크롤을 사용하고 중첩 스크롤은 피한다.
- **확정:** 빌리지 설정의 고정 영역과 스크롤 영역은 미묘한 배경 톤 차이로 구분한다. 스크롤 경계·현재 위치가 알아보기 쉬워야 한다.
- 닫기와 핵심 조작은 내용 스크롤과 무관하게 보이고 터치 가능해야 한다.

### UI-06. 설정 배경 가림막

- **확정:** 설정을 열 때 검게 만드는 박스가 일부 엉뚱한 영역만 덮는 현상을 고친다.
- 가림막은 설정 패널의 부모 크기에 갇히지 않고 **전체 게임 뷰포트**를 덮는다. 패널은 그 위에 표시한다.
- 모바일 안전 영역·화면 회전·해상도 변경·다른 모달 위 열기에서 검사한다. 뒤 화면 입력이 새거나 닫은 뒤 투명 가림막이 남지 않아야 한다.
- Roblox 기본 시스템 UI까지 임의로 덮으려 하지 않는다. 대상은 게임이 제어하는 전체 화면 영역이다.

## 3. 플레이 선택·맵 상세·전투 배치 UI

### UI-07. 플레이 선택 목록

- **확정:** 플레이 선택 화면의 강아지 아이콘은 현재 보이는 가로·세로 크기의 약 **50%**로 줄인다. 버튼 터치 영역까지 절반으로 줄이지 않는다.
- **확정:** 모드 이름/설명은 **스토리모드 / 협동모드 / 도전모드**로 통일한다.
- 설명 초안: 스토리모드 ‘맵을 차례로 클리어하며 강아지 수비대를 성장시켜요.’ / 협동모드 ‘친구와 역할을 나누어 함께 수비해요.’ / 도전모드 ‘이어지는 공세에 맞서 기록에 도전해요.’ 실제 모드 규칙과 맞게 최종 교정한다.

### UI-08. 난이도와 클리어 표시

- **확정:** ‘맵 난이도’ 제목과 ‘쉬움 / 보통 / 어려움’이 너무 붙어 있으므로 간격과 그룹을 분리한다.
- **확정:** 왼쪽 맵 목록의 ‘장난감방’ 같은 맵 이름 아래에 **난이도별 정보/선택(쉬움·보통·어려움)**을 표시한다. ‘난이도 별로’라는 말을 별 모양 아이콘의 필수 요청으로 단정하지 않는다. 별 아이콘을 보조로 쓴다면 맵 고유 난이도인지 선택 난이도인지 구분한다.
- **확정:** 오른쪽에는 해당 맵의 **쉬움·보통·어려움 각각의 클리어 여부**를 보여준다. 클리어/미클리어/잠김과 현재 선택 난이도를 같은 표시로 겸용하지 않는다.
- 체크·잠금·선택 테두리와 짧은 글자를 함께 사용한다. 도전 기록과 스토리 클리어를 혼동하지 않는다.

### UI-09. 오른쪽 맵 미리보기 확대

- **확정:** 상세 영역에서 맵이 더 크게 보여야 한다. 시작 전 길과 배치 위치를 보고 전략을 계획할 수 있어야 한다.
- 텍스트와 카드 여백 때문에 맵이 밀려나지 않게 미리보기 면적을 우선 확보한다. 전체 경로·입구·출구·배치 가능 영역을 읽을 수 있게 한다.
- 작은 기기에서 경로가 식별되지 않으면 확대 보기/접기 등 최소 조작을 제공한다. 핵심 경로를 자른 장식용 썸네일로 대체하지 않는다.
- 실제 플레이 맵과 경로·분기·장애물·배치 규칙이 같은 자료를 사용한다.

### UI-10. 풍타디를 참고한 배치·타워 설명

- **확정:** 풍선 타워 디펜스를 다시 참고해 전투 UI를 수정한다. 현재 타워를 선택해 설치하는 창은 너무 작고 설명이 부족하다.
- 다음 담당자가 실제 참고 화면/버전을 확인하고, 맵과 선택 목록의 관계·선택 상태·업그레이드 정보 계층·터치 동선을 기록한다. 이 전달 단계에서 새 참고 조사를 완료한 것은 아니다.
- 선택 카드에는 **이름, 역할, 소환 가격, 공격/지원 방식, 핵심 효과**를 먼저 보여준다. 상세에는 공격력·공격 간격 또는 초당 공격 수·범위·탐지·다음 진화 변화·조합 연결을 제공한다.
- 지원견에 가짜 DPS를 표시하지 말고 버프/약화/탐지 수치와 범위를 표시한다. 특수 상태·방어 무시와 경로 관통을 구분한다.
- 배치 전 범위·가능/불가능·비용 부족 사유와 취소 동작을 명확히 한다. 실제 타워 선택 후 강화/판매 상태와 신규 소환 상태도 구분한다.
- 큰 창이 맵을 덮어 전투 상황을 볼 수 없게 만들지 않는다. 메뉴를 열고도 배치·취소·다른 타워 선택이 가능한지 실플레이한다.

## 4. 티어·특전·프로필

### UI-11. 티어와 테두리 통일

- **확정:** 티어가 올라갈 때 특수효과를 넣는다. 상승 전후 티어가 한 번에 읽히고 반복 열기로 다시 보상을 주지 않게 한다.
- **확정:** C–S 티어 스타일의 테두리를 적용하고 해당 티어에 따라 바뀌게 한다. 기존 게임의 등급 체계를 사용하고 임의로 새로운 등급은 추가하지 않는다.
- **확정:** 빌리지 티어창에도 게임과 동일한 티어 아이콘을 반영한다. 등급별 아이콘·색·테두리는 공통 정의를 공유한다.
- **확정:** 티어창의 강아지 크기를 줄여 단계·조건·강화 정보를 위한 공간을 확보한다. 구체 축소율은 실제 레이아웃에서 정하며 플레이 선택의 50%를 여기에 자동 적용하지 않는다.
- 테두리 색뿐 아니라 C/B/A/S 문자·아이콘/형태로도 구분한다. 작은 썸네일·비활성·선택 상태에서도 읽히게 한다.
- 이 요청의 테두리는 티어 연동이다. 별도 유료 테두리 상점이나 임의 테두리 선택 기능까지 요구한 것으로 확대하지 않는다.

### UI-12. 특전 표시

- **확정:** 기초 시너지 완성을 강한 색 차이만으로 나누던 표시를 **미묘한 톤 차이 + 점선**으로 정리한다.
- 권장안: 미완성은 낮은 톤·점선, 완성은 약간 밝은 톤·실선/체크. 선택됨·해금 가능·부족·완성의 의미를 범례와 상태 문구로 고정한다.
- 조건 진행도(예: 2/3)와 부족 견종/진화 조건을 함께 보여 색을 구별하기 어려워도 이해할 수 있게 한다.
- **확정:** 특전 소개의 **‘찾고 쫓고 마무리해요’** 문구를 제거한다. 실제 문자열에 공백·조사가 다르면 해당 안내 문장 전체를 찾아 제거한다.

### UI-13. 내 프로필 대표 이미지

- **확정:** 내 프로필에서 기존 강아지 일러스트 중 대표 이미지를 선택·설정할 수 있게 한다.
- 그리드 미리보기·현재 선택·적용/취소·저장 후 재접속 복원을 제공한다. 선택 ID를 저장하고 원본 이미지를 사용자 데이터마다 복제하지 않는다.
- 선택 가능 목록은 기존 사용 가능한 일러스트를 기준으로 한다. 사용자가 요청하지 않은 외부 이미지 업로드나 유료 아바타 구매는 추가하지 않는다.
- 신규/잠긴 견종의 초상 사용 허용 여부는 해금 규칙과 함께 결정하고 잠겨 있으면 이유를 표시한다. 기존 선택이 더는 유효하지 않으면 기본 시바 이미지로 안전하게 복원한다.

## 5. 캐릭터·진화·스킨·공격 모션 제작

### ART-01. 새 견종 스타일 검사와 필요한 것만 재생성

- **확정:** 기존 캐릭터는 색면이 분리되어 있는데 추가 견종에 그라데이션이 많다. 모든 견종을 비교해 **필요한 것만** 다시 생성한다.
- 기본 6종 원화와 같은 크기로 나란히 놓고 선 두께, 명암 방식, 코·눈, 머리/몸 비율, 윤곽의 선명함, 귀·꼬리·발을 비교한다.
- 기준: 2D 일러스트, 큰 머리·짧은 몸·다리, 작은 코·검정 점눈, 일관된 짙은 갈색 외곽선, **분리된 평면 색 영역**. 부드러운 3D 그라데이션·광택·과도한 음영을 새 기본 스타일로 쓰지 않는다.
- 원본과 교정본, 재생성 대상 선정 이유를 남긴다. 정상 원화까지 일괄 재생성해 캐릭터 인상을 바꾸지 않는다.

### ART-02. 앞으로 추가하는 캐릭터의 필수 에셋

- **확정:** 스킨의 진화 이미지와 공격 모션 이미지를 생성해 스킨창에 반영한다. 앞으로 캐릭터를 추가할 때마다 진화와 공격 모션을 필수 제작한다.
- 기본형·성장 1/2/3단계·최종 분기 2개 중 실제 시스템에 존재하는 모든 표시 상태를 빠짐없이 대응한다. 별도 기본형과 1단계가 같은 상태면 중복 제작 대신 명시적으로 재사용한다.
- 각 실제 장착 스킨은 해당 성장 상태의 대기·공격 동작을 갖춘다. 골든·모더콜리는 **지원 동작**으로 제작하며 피해 모션을 다시 만들지 않는다.
- 공격 동작은 준비 → 발사/방전/짖음/지원 → 회복의 연결을 확인한다. 투사체가 입에서 떠나는 프레임, 뼈/원반의 부재·복귀, 효과 발생점을 맞춘다.
- 스킨창에는 장착 모습, 성장별 보기, 공격/지원 모션 미리보기를 제공하고 실제 장착 상태가 게임에서도 동일해야 한다.
- 필수 에셋이 없는 견종·스킨을 정상 완성처럼 노출하지 않는다. 개발 중 임시 이미지는 상태를 명시하고 출시 목록과 구분한다.
- 캐릭터·효과·그림자·배경·UI는 가능하면 분리하고 투명 이미지에 검은/흰 네모가 남지 않게 검사한다.

### ART-03. 공격할 때 작아지는 문제

- **확정:** 시바뿐 아니라 전 견종을 검사한다. 실제 게임 화면의 대기·공격 두 상태를 나란히 비교해 최대한 같은 몸 크기를 유지한다.
- PNG 전체 캔버스 크기만 같게 맞추지 않는다. 투명 여백·얼음/번개·투사체가 커졌다고 강아지 몸까지 자동 축소하지 않는다.
- 원화의 실제 몸 영역, 머리 폭, 발바닥 기준점/피벗을 정의한다. 대기·준비·타격·회복의 기준을 공유하고 의도한 동작만 변하게 한다.
- 이펙트와 분리하거나 프레임별 기준점 메타데이터로 맞춘다. 현재 렌더러에 가장 적은 변경으로 가능한 방식을 쓴다.
- 권장 검사: 의도한 자세 변화 제외 몸의 시각적 스케일 차이 약 5% 이내를 목표로 하고, 숫자 통과만으로 끝내지 말고 루프 영상과 실제 게임에서 확인한다. 접히거나 숙이는 자연스러운 자세를 강제로 늘려 맞추지 않는다.
- 동일 카메라·줌·배치 위치·단계에서 대기/공격 전후 화면을 기록한다. 메뉴 미리보기와 전투 표시 크기도 따로 확인한다.

### ART-04. 조합별 스킨 콘셉트

- 전투 MD 11절의 6개 보드(과열 폭파, 사냥 예고, 꽁꽁 놀이, 물장구 찌릿, 시바 오총사, 냄새 추적대) 및 지원견 개편 시안을 실제 이미지로 제작한다.
- 콘셉트 보드는 방향 탐색 자료다. 장착 가능한 스킨으로 구현한 것은 진화·공격/지원 에셋, 가격·보너스·저장 ID, 게임 연결까지 완성 후 별도 표시한다.
- 그림만 보고 기능을 오해하지 않게 사냥·놀이·무리 구분과 기본 견종 실루엣을 유지한다.

### PROG-03. 30포인트와 레벨 지급의 관계 — 결정 필요

기존 대화의 총 30포인트와 이번 레벨당 1포인트를 동시에 그대로 적용하면 31레벨 이후 규칙이 필요하다. **아래는 충돌을 줄이는 권장안이며 사용자 확정이 아니다.**

- 누적 획득 포인트와 현재 배분 포인트를 분리한다.
- 계정은 레벨마다 1포인트를 계속 얻고, 전투에 적용되는 배분은 최대 30포인트로 제한한다.
- 31포인트 이상 잔여는 보존하되 사용처는 미정으로 둔다. 임의의 추가 능력치·재화 전환·유료 확장에 쓰지 않는다. 예비 포인트가 실제 쓸모 없이 쌓이는 문제도 함께 제안한다.
- 레벨 1의 초기 지급을 포함할지 명확히 정한다. **초기안은 레벨 1에 1포인트, 레벨 L 누적 L포인트**다. 기존 시스템이 레벨업 횟수 기준이면 L−1과 혼동하지 않도록 이관한다.
- 레벨 40에서 8종이 모두 열려도 특전 40포인트가 전투에 몰래 적용되지 않게 검사한다. 반대로 31레벨부터 획득 보상을 조용히 없애지 않는다.
- 30 상한 자체를 늘리는 선택지는 별도 밸런스 변경이다. 이 해석이 확정되지 않은 채 저장 형식과 경제를 굳히지 않는다.

### PROG-04. 경험치·저장·소급

- 경험치 곡선은 실제 평균 한 판 시간과 목표 해금 기간을 계산해 정한다. 이 문서에 확정 XP 수치는 없다.
- 여러 레벨을 한 번에 올릴 때 모든 포인트·5레벨 해금을 빠짐없이 처리하고 재접속으로 중복 지급하지 않는다.
- 기존 계정 레벨·보유 견종·조각·스킨·특전을 보존한다. 새 레벨 규칙 때문에 이미 가진 견종을 회수하지 않는다.
- 소급 지급은 기존 지급 내역과 차이만 처리하고, 저장 버전/보상 수령 기록으로 반복 이관을 막는다.

## 7. 사용량 기반 견종 조각

### ECON-01. 확정 방향

- 강아지 조각은 **해당 견종을 실제 게임 중 얼마나 사용했는지**에 근거해 지급한다.
- 단순 랜덤 균등 지급이나 직접 킬 수만으로 결정하지 않는다. 골든·모더콜리는 직접 피해가 없으므로 지원 역할을 인정한다.
- 결과창에 이번에 기여한 견종·조각 수·주요 기준을 설명한다.

### ECON-02. 권장 집계안 — 수치는 실제 비교 후 확정

- 서버/권한 있는 전투 기록으로 견종별 유효 활동 시간을 모은다. 공격수는 적을 실제로 상대하는 시간·유효 피해/제어, 지원견은 아군의 실제 전투 중 버프·탐지·디버프 기여를 측정한다.
- 지원 반경에 가만히 서 있는 비전투 아군이나 이미 죽은 적에게 효과를 반복 표시하는 시간은 유효 기여가 아니다.
- 배치 시간만 보상하는 방치 파밍과 막타만 인정하는 지원견 차별을 모두 피한다. 역할별 기여를 정규화해 지원견과 공격견의 시간당 획득량을 비교한다.
- 같은 견종을 많이 놓는 경우 사용량은 반영하되 조각 총량이 개체 수만큼 무제한 늘지 않게 한다. 초기안은 판당 조각 예산을 정하고 견종별 기여 비율로 나누는 방식이다.
- 예시 구조: `견종 점수 = 유효 활동 시간 × 역할 기여 보정`, `견종 배분 비율 = 점수 / 전체 유효 점수`. 정확한 보정·최소 참여·반올림·보상량은 미정이다.
- 정수 조각의 잔여를 나눌 때 총 지급량을 보존한다. 기여가 0이면 0으로 처리하고 분모 0·음수·무한값을 방어한다.
- 합체 전까지 5종이 쌓은 기록은 보존한다. 합체 후 추적대의 사용량은 **소모한 5종에 총량 보존하며 1/5씩 배분**하는 초기안을 권장한다. 1초 활동을 5종 각 1초로 적어 총 5초를 주지 않는다.
- 시바 오총사는 같은 견종 시바의 기록으로 합산하되 파편 피해를 다섯 번 중복 집계하지 않는다.
- 판매·재소환·종료 직전 잠깐 배치·협동 중복·분열 적·재접속에서 악용을 검사한다. 실패/중도 이탈 보상 정책은 기존 게임 규칙과 맞춰 명시한다.

## 8. 스킨 보너스·멍코인

### ECON-03. 사용자 확정 방향

- 스킨은 착용하면 **라운드 종료 시 티켓 획득량을 일정 % 증가**시킨다. **중복 불가**다.
- 티켓보다 귀한 스킨 구매 자원 이름은 **멍코인**이다.
- 멍코인은 라운드 클리어 1개, 주간 퀘스트 클리어 1개 같은 적은 공급을 고려한다. 이 지급 예시는 희소하게 설계하라는 의도다.
- 스킨 가격은 **최저 10멍코인부터** 시작한다. 상세 가격표·공급 주기·보너스 %는 아직 정하지 않았다.

### ECON-04. ‘라운드’ 정의 — 구현 전에 확정할 것

- ‘적 한 웨이브’와 ‘맵 한 판 최종 클리어’를 구분한다. 멍코인을 매 웨이브마다 주면 10멍코인 스킨의 희소성이 달라진다.
- **권장안:** 멍코인 +1은 개별 웨이브가 아닌 **맵 한 판 최종 클리어**. 주간 퀘스트의 지정 보상도 완료·수령당 1회다. 사용자 확정으로 기록하지 않는다.
- 무한 도전은 최종 클리어가 없으므로 보상 가능한 도달 목표·정산 시점을 별도 정의한다. 매 웨이브 반복 지급으로 대체하지 않는다.
- 스킨 티켓 보너스가 붙는 ‘라운드 종료’도 현재 티켓 지급 단위와 대조해 명시한다. 티켓이 원래 지급되지 않는 웨이브에 새 기본 보상을 임의 생성하지 않는다.

### ECON-05. 중복 불가의 권장 구현

- 본인이 실제 장착한 유효 스킨 중 **가장 높은 보너스 하나**를 자신의 티켓 정산에 적용하는 안을 권장한다. 여러 강아지·중복 스킨·파티원 스킨으로 합산하지 않는다.
- `추가 티켓 = 기본 정산 티켓 × 선택된 단일 보너스율`을 한 번 계산한다. 이미 보너스가 붙은 금액에 다시 적용하지 않는다. 정수 처리 규칙을 통일한다.
- 착용 시점은 **보상 구간 시작 시 확정**하는 초기안을 권장한다. 종료 직전 잠깐 갈아입기로 보너스를 얻는지 실제 정책을 정하고 설명한다. 중간 변경은 다음 보상 구간부터 반영한다.
- 비교용 최초 후보는 **+5%** 정도다. 확정이 아니며 +3/+5/+10%의 누적 티켓·진행 속도 차이를 비교한다. 이 효과를 공격력·멍코인·견종 조각 보너스로 확대하지 않는다.
- 티켓이 성장 재화라면 스킨이 장기 진행 속도에 영향을 준다는 점을 경제 QA에 포함한다. 비싼 스킨이 반드시 더 높은 수익률을 가져야 한다고 가정하지 않는다.
- UI 문구 예시: ‘착용 효과: 정산 티켓 +5% · 동일 효과 중복 적용 불가’. 실제 채택률·정산 단위로 치환한다.

### ECON-06. 희소성·상점·보상 정합성

- 최저 10멍코인이라면 맵 클리어마다 1개 기준 보너스 없이 **10회 적격 클리어**가 필요하다. 한 판 시간·승률·주간 보상에 따라 실제 소요 시간이 달라진다.
- 짧은 쉬운 맵 반복이 유일한 최적 수급인지, 협동/도전이 불리한지 비교한다. 필요 시 보상 대상 난이도·첫 클리어·정산 한도 후보를 제안하되 임의의 일일 숙제 제한을 확정하지 않는다.
- 스킨 가격, 보유 멍코인, 부족량, 구매 후 잔액, 보유/착용 상태를 표시한다. 티켓과 멍코인의 아이콘·색·사용처를 명확히 구분한다.
- 결제와 지급은 한 번만 처리한다. 연속 클릭·동시 요청·재접속·이미 보유한 스킨 재구매에서 재화 차감·아이템 지급이 중복되지 않아야 한다.
- 주간 퀘스트의 주차/시간대·보상 수령 기록과 전투 보상 ID를 고정한다. 클라이언트가 횟수나 잔액을 직접 정하게 하지 않는다.
- 티켓·멍코인·전투 사료·견종 조각은 별개 재화다. 골든의 사료 생산을 없앴다고 계정 재화 정산을 골든 버프로 다시 연결하지 않는다.
- 현금 구매, 확률형 상자, 멍코인 유료 판매는 이번 요구에 없다.

### 밸런스 비교와 보고

- 같은 계정 레벨·해금 상태·투자 비용·특전·웨이브/시드로 비교한다. 고레벨 계정만으로 ‘초반 플레이 가능’을 판정하지 않는다.
- 기본 6종 신규 계정부터 5/10/15/20/25/30/35/40레벨 진행 경로를 점검한다. 아직 해금되지 않은 견종을 필수 카운터로 쓰지 않는다.
- 스킨 없음/있음의 전투 승률과 계정 티켓 누적을 분리한다. 선택형 장식·소폭 수익 보너스가 진행 필수 구매가 되는지 확인한다.
- 처치 성장·원소 제어·오라·합체·사용량 조각이 서로 중복 보상/무한 루프를 만들지 검사한다.
- 실제 플레이에서 나온 값, 수식상 예상, 간이 시뮬레이션을 구분해 기록한다. 수치가 어긋나면 수정하고 같은 조건으로 재검사한다.
