다른 동생말보다 무언가를 만드는 아버지의 모습을 기억무관심만으로 설명되지 않는 모습을 보탬. 초반부터 아버지를 변호하지는 않음

아래는 원안을 NFC 키트와 웹으로 옮기는 구현 제안입니다. 실제 게임 화면이나 기능을 개발한 상태는 아닙니다.

만들 경험웹에서 보여 줄 것키트·NFC와 연결
오래된 연락처 복원가족 프로필, 생일 입력, 정답 후 열리는 대화연락처 카드와 시작 안내. 발신 기능 없이 웹 안에서 진행
고객 기록 모으기낡은 주문서와 사진을 읽기 편한 증거 화면으로 구성주문서에 NFC와 QR을 함께 제공. 여러 기록은 같은 화면에서 단계별로 열 수 있음
가족의 증언 듣기인물별 말투, 대화 간격, 짧은 음성과 자막사진·편지 카드로 연결. 소리를 켜지 않아도 모든 단서를 읽을 수 있게 구성
마지막 기록 공개수집한 단서가 합쳐지는 주문서, 조용히 읽는 편지 화면플레이어가 휴대하는 봉인 봉투와 연결하는 방식 검토
완주 후 기억 남기기사건명과 날짜가 있는 기념 이미지정답·고객 정체가 드러나지 않는 작은 기념 카드. 상세페이지·포장과 같은 디자인 사용
이야기 속 구두와 실제 판매 키트의 구성은 따로 결정해야 합니다.

원안의 상자·구두는 이야기의 결말입니다. 실제 구두를 매 세트에 넣을지는 아직 정하지 않았습니다. 배우 없이 운영하는 첫 방식으로는 휴대하는 마지막 봉투 + 웹에서 구두와 편지를 공개하는 구성을 제안합니다. 서울숲에 상자를 두고 찾아가게 하는 방식은 설치·분실·관리 협의를 별도로 검토해야 합니다.

기존 원가표는 종이 키트·NFC 5장 기준입니다. 이 성수 기획의 태그 수, 늘어나는 인쇄물, 실제 구두·모형·특수 상자, 장소 비용과 추가 제작 시간은 확정하지 않았으므로 기존 8,000원을 성수 완성품의 확정 원가로 쓰면 안 됩니다.

  • A · 장소 조사: 현재 운영 중인 후보 7~10곳, 지역성과 실제 사용 조건 확인.

  • C · 장소별 게임: 무엇을 관찰하고 어떤 증거를 연결하는지, 힌트와 대체 장소까지 설계.

  • F · 현장 인력 없는 엔딩: 마지막 소품을 받는 방법, 비가 올 때의 대안, 봉인과 웹 공개 순서 검증.

10 · NFC와 제작 방식

태그에는 주소를, 이야기는 웹에 담습니다.

NFC는 휴대전화를 가까이 대면 정보를 읽는 기능입니다. 이번 사양에서는 작은 스티커가 웹 주소를 알려 주고, 사진·음성·문제는 휴대전화의 인터넷 화면에서 보여 줍니다.

1. 휴대하는 증거 카드

NFC 스티커에 주소 기록

짧은 보안 웹 주소를 넣습니다. 카드는 이야기 속 도장·우편·기록물처럼 디자인합니다.

2. 휴대전화로 열기

태그를 대고 알림 선택

기기의 기본 읽기 기능으로 링크를 엽니다. 읽히지 않으면 QR이나 수동 코드를 사용합니다.

3. 구매 확인 후 진행

웹에서 증거·힌트 보기

키트의 시작 코드와 진행 기록을 확인합니다. 태그와 현장 관찰 정보를 함께 사용합니다.

NXP NTAG213 안내: 사용자 메모리 144바이트의 태그입니다. 전체 게임을 저장하기보다 짧은 주소를 넣는 사양에 맞습니다. Apple 공식 문서: iPhone XS 이후 기기의 기본 태그 읽기와 동작 조건을 설명합니다.

직접 디자인할 때 챙길 점

  • 밝은 야외에서도 읽히는 화면. 글자 대비를 높이고 중요한 조작 버튼은 충분히 크게 만듭니다.
  • 소리 없이도 진행. 음성에는 글을 함께 제공하고, 영상 자동 재생을 기본으로 두지 않습니다.
  • 한 화면에 한 가지 행동. “무엇을 찾고, 어떤 카드를 보고, 무엇을 입력하는가”를 짧게 안내합니다.
  • 힌트는 조금씩. 관찰 방향→조합 방법→거의 정답 순서로 도움을 늘립니다.
  • 공유 이미지는 스포일러 없이. 정답 대신 사건명·선택 결과·기념 문양을 보여 줍니다.

실물과 실제 휴대전화에서 검사

  • 아이폰·갤럭시 모두 확인. 화면 잠금·카메라 사용 등 기기 상태에 따라 읽기가 달라집니다.
  • QR·수동 코드 준비. NFC가 안 돼도 구매한 게임을 진행할 수 있게 합니다.
  • 완성된 카드로 확인. 태그 겹침, 금속 상자, 코팅과 재질이 읽기에 영향을 줄 수 있습니다.
  • 새로고침 후 이어 하기. 게임을 닫았다가 다시 열었을 때 진행을 복구할 방법을 검증합니다.
  • 가볍고 짧은 자료. 큰 동영상에 의존하지 않고 사진·글·짧은 음성으로 데이터 부담을 줄입니다.
개발자에게 전달할 짧은 요구사항

첫 버전은 “NFC에 기록한 HTTPS 주소를 휴대전화가 열고 웹게임으로 연결하는 방식”으로 요청합니다. 웹페이지가 직접 NFC를 읽는 Web NFC와 구분합니다. Google 공식 문서는 Web NFC를 Android용 Chrome의 기능으로 설명하므로, 이를 모든 휴대전화에서 같은 방식으로 쓰는 구조를 전제로 잡지 않습니다.

최소 기능은 키트 시작 코드, 이용 권한, 정답 확인, 단계별 힌트, 진행 복구, 언어 선택, 기본 오류 기록입니다. 태그 주소를 읽기 전용으로 잠가도 주소 공유까지 막히는 것은 아닙니다. 키트별 사용권 관리가 필요하고, 강한 정품 태그 확인은 별도 보안 태그·서버 범위로 견적합니다.

Google 공식 Web NFC 안내 · Apple의 기본 태그 읽기 안내

실제 장소에 가야 풀리는 이유를 만듭니다.

키트의 NFC를 찍은 사실만으로 현장에 갔다고 증명되지는 않습니다. 건물 외관·공공 문양·방향처럼 주변을 봐야 알 수 있는 단서와 연결합니다. 바뀌기 쉬운 팝업·가격표·메뉴를 필수 정답으로 쓰면 수정과 고객 대응 비용이 늘어날 수 있습니다.

발주 전에 같은 사양으로 비교할 항목

태그 종류·크기·접착 재질·인쇄 여부·주소 기록·읽기 전용 설정·불량 교체 조건, 책자의 크기·쪽수·종이·인쇄 색·코팅, 봉투와 카드 수량, 박스 규격, 조립·검사 시간, 배송·부가세를 적어 견적을 비교합니다. 태그 5장 기준으로 100세트는 500장, 500세트는 2,500장이 필요합니다.

공공 시설물에 태그를 붙이거나 상점 안을 필수 코스로 쓰는 경우 관리 주체와 협의가 필요합니다. 주거 출입구·좁은 통로·상점 대기줄을 퍼즐 거점으로 잡지 않습니다. 이 보고서의 비용에는 그런 장소 설치·임대·현장 인력이 포함되어 있지 않습니다.
